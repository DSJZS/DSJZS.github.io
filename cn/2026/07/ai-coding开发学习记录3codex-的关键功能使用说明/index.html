Subagent

介绍以及简单使用

Codex APP 和 Codex CLI 都是默认支持创建 Subagent 的。

不过 Subagent 不会自动创建，必须明确告知 Codex 要几个、每个干什么等自定义内容才会创建。

每个 Subagent 的生存周期由主 Agent 和 Codex Runtime 自行管理。当然用户也可以通过提示词等方式主动控制。

自定义 Subagent

很多时候 Codex 的 Agent 自动创建的 Subagent 不满足我们实际的业务需求，而且每次可能都不一样。

所以实际的项目中一般需要我们使用自定义 Subagent 。

详细资料参考 Configuration Reference 和 Subagents 。

下文介绍最基础的部分。

基础配置

有两种方式：

  • 全局配置，配置文件位于： ~/.codex/config.toml 。
    用于提供默认配置 。
    还有下文提到的线程数、深度限制。
  • 项目级配置，配置文件位于： <project>/.codex/config.toml 。
    用于配置当前项目专用 Subagent 。

为了让 Codex 受监管地创建 Subagent 。一般会在 ~/.codex/config.toml 等地方田间如下的内容：

[agents]
max_threads = 6
max_depth = 1

这两个字段分别为：

  • max_threads - 最大线程数，每个 Subagent 要单独开个线程，相当于规定了最多并行几个 Subagent。
  • max_depth：最大深度，表示最多嵌套几层 Subagent。一般为 1，避免嵌套过多。

Subagent 配置

同样分两种位置存放：

  • 全局定义，配置文件位于： ~/.codex/agents/<name>.toml 。
    用于定义默认 Subagent 。
  • 项目级定义，配置文件位于： <project>/.codex/agents/<name>.toml 。
    用于定义当前项目专用 Subagent 。

定义一个新的 Subagent 。格式大概如下：

name = "Agent 名称"
description = "什么时候适合调用这个 Agent"
developer_instructions = "Agent 的角色、职责、工作边界和输出要求"

model = "可选，指定使用的模型"
model_reasoning_effort = "可选，指定推理强度"
sandbox_mode = "可选，指定文件和命令权限"

Bug 说明与解决方案

目前 GPT 5.5/5.6 貌似会有 Bug 无法读取自定义配置。

创建 Subagent 会走内部的工具，而非用户的配置。

目前貌似最方便的办法就是给降到 GPT 5.4 启动 Codex ，命令为：

codex -m gpt-5.4
